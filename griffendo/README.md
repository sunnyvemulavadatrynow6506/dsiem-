# Griffendo — Windows Event Intelligence (v5.1)

- `docs/REPORT.md` — v5.1 report (§0: start-up hang and speed fixes): detection and correlation engine, rule inventory, Detections page, time filters; tests, measurements, limitations
- `docs/REPORT_v4.md` — v4 report: rule switches + history, anomaly timeline, 24-hour graph, refresh
- `docs/REPORT_v3.md` — v3 report: collection, persistence, rule management, coverage
- `docs/REPORT_v2.md` — the v2 (anomaly detection) report
- `docs/perf/` — raw benchmark results (v2 to v5)
- `docs/rules_inventory.json`, `docs/Griffendo_v5_Rule_Inventory.xlsx` — every inspected Elastic and Wazuh rule with its status, reason and licence
- `src/logplatform/detection/engine/` — detection engine · `src/logplatform/detection/rules/` — one Python file per rule, loaded through `rules/index.py`
- `tools/rules_import/` — Elastic (TOML: EQL/KQL) and Wazuh (XML) translators; `generate.py` regenerates the rule files and inventory
- `docs/Griffendo_Anomaly_Event_IDs_v2.xlsx` — built-in catalog, difference report
- `src/` — backend (`logplatform/` receiver, `agent/` collector) · `web/` — dashboard
- `catalog/anomaly_catalog.json` — built-in rules (generated by `tools/build_catalog.py`)
- `tests/` — `python -m pytest tests` (synthetic events only; no Windows needed)
- `tools/benchmark.py`, `tools/benchmark_collector.py`, `tools/benchmark_existing.py`, `tools/benchmark_v4_queries.py` — measurements
- `tools/ui_acceptance_v5.js` — Playwright UI acceptance checks against the synthetic demo (v5)
- `tools/benchmark_v5.py` — page-load benchmark (runs against v4 or v5 sources)
- `tools/demo_server.py` — dashboard + continuous collector against a synthetic live log, any OS
- `tools/repack_exe.py` — rebuild Griffendo.exe from the original exe + these sources; `tools/verify_exe.py` checks the result

Useful settings (environment variables):

| Variable | Default | Meaning |
|---|---|---|
| `GRIFFENDO_STATE_DIR` | `%LOCALAPPDATA%\Griffendo` | Data folder (events DB, rule settings, collector state) |
| `GRIFFENDO_STORAGE` | `disk` | `memory` = v1/v2 behaviour (nothing kept after exit) |
| `GRIFFENDO_RETENTION_DAYS` | `14` | Events older than this are pruned (detections are kept) |
| `GRIFFENDO_UI_REFRESH_SECONDS` | `3` | How often the browser checks for new data |
| `WINLOG_INTERVAL_SECONDS` | `2` | Collector live polling interval |
| `WINLOG_BACKEND` | `auto` | `native` (Windows Event Log API), `powershell`, or `auto` |
| `WINLOG_BATCH_SIZE` | `5000` | Events per delivery request |
| `WINLOG_LIVE_BATCH` / `WINLOG_BACKFILL_BATCH` | `2000` | Events per read |
| `WINLOG_BACKFILL_HOURS` | `336` | History read for System/Security/Setup/Application |
| `WINLOG_SUPPLEMENTARY_LOOKBACK_HOURS` | `192` | History read for added channels |
| `LOGPLATFORM_MAX_INGEST_EVENTS` | `10000` | Receiver limit per request (was fixed at 2,000) |
| `WINLOG_MODE` | `continuous` | `snapshot` = read once at launch (v1/v2) |
| `GRIFFENDO_ANOMALY_REFRESH_SECONDS` | `60` | Detections view auto-refresh (collection is not affected) |
| `GRIFFENDO_REFRESH_TIMEOUT_SECONDS` | `20` | How long the Refresh button waits for the collector's immediate pass |
| `GRIFFENDO_EVAL_WAIT_SECONDS` | `2` | Switching a rule on waits this long; larger 7-day re-evaluations continue in the background |
| `GRIFFENDO_EVAL_CHUNK` | `2000` | Events per re-evaluation chunk |

Detection engine (v5):

| Variable | Default | Meaning |
|---|---|---|
| `GRIFFENDO_DETECTION_WORKER` | `1` | `0` = do not start the background detection worker (tests) |
| `GRIFFENDO_DETECTION_BATCH` | `2000` | Events the worker processes per pass |
| `GRIFFENDO_DETECTION_WINDOW_DAYS` | `7` | Look-back when a rule is switched on or a custom rule is saved |
| `GRIFFENDO_SEVERITY_THRESHOLDS` | `90,70,40,20` | Risk score lower bounds for Critical, High, Medium, Low |
| `GRIFFENDO_SIGNAL_HALF_LIFE_MINUTES` | `15` | Decay of a signal's weight within a detection |
| `GRIFFENDO_AGGREGATION_MINUTES` | `30` | Event-time bucket used to group signals into one detection |
| `GRIFFENDO_STATE_MAX_KEYS` / `GRIFFENDO_STATE_MAX_PER_KEY` | `50000` / `5000` | Memory caps for correlation windows |
| `GRIFFENDO_PROCESS_TTL_HOURS` / `GRIFFENDO_PROCESS_MAX` | `24` / `200000` | Process table lifetime and size |
| `GRIFFENDO_LOGON_TTL_HOURS` / `GRIFFENDO_LOGON_MAX` | `24` / `50000` | Logon session table lifetime and size |
| `GRIFFENDO_BEHAVIOR_LAMBDA` | `0.01` | Adaptation rate λ in μ ← (1−λ)μ + λx |
| `GRIFFENDO_BEHAVIOR_DECAY` | `0.98` | Daily decay of behaviour counts |
| `GRIFFENDO_BEHAVIOR_ALERT_THRESHOLD` | `0.6` | Behaviour score that raises a signal (Active stage) |
| `GRIFFENDO_BEHAVIOR_LEARN_MAX` | `0.5` | Only events scoring below this update the model |
| `GRIFFENDO_BEHAVIOR_MIN_OBSERVATIONS` / `GRIFFENDO_BEHAVIOR_MIN_LEARNING_DAYS` | `5000` / `2` | Learn → Shadow requirements |
| `GRIFFENDO_BEHAVIOR_MIN_SHADOW_HOURS` | `24` | Minimum time in Shadow before Active |
| `GRIFFENDO_BEHAVIOR_SHADOW_TARGET` / `GRIFFENDO_BEHAVIOR_SHADOW_MAX_FP` | `2.0` / `0.3` | Shadow → Active: alerts per 1,000 events and false-positive ratio limits |
| `GRIFFENDO_BEHAVIOR_STABLE_NOVELTY` / `GRIFFENDO_BEHAVIOR_STABLE_VARIANCE` | `0.05` / `0.25` | Stability tests for leaving Learn |
| `GRIFFENDO_BEHAVIOR_DRIFT_MODERATE` / `GRIFFENDO_BEHAVIOR_DRIFT_LARGE` | `3.0` / `10.0` | Drift levels: Adapt, or back to Learn |
| `GRIFFENDO_CRITICAL_ASSET` | `0` | `1` raises the context multiplier for this host |
